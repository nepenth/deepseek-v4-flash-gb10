# 2026-08-21 Dual-HCA QSFP merge

## Decision

Keep the two-HCA NCCL merge as the live 0731 fabric config. Do not rebase
the vLLM image.

## Evidence

nccl-tests all_reduce, 1 GiB, NCCL 2.30.7, serve down:

- single HCA, MTU 1500: 12.53 GB/s busbw (~100 Gb/s)
- single HCA, MTU 9000: 12.59 GB/s (jumbo alone is not the win)
- both QSFP virtual HCAs + `NCCL_IB_MERGE_NICS=1` + GID index unset +
  MTU 9000: 23.55 GB/s busbw (~188 Gb/s)

Think-off decode on the same ignore_eos protocol, clocks ~2093 MHz:

- 256 C1: 46.6 → 77.4 tok/s, TTFT 376 → 201 ms
- 2048 C1: 55.3 → 78.1 tok/s, TTFT 394 → 181 ms
- 32k×6: 31.6 → 47.5 tok/s, TTFT 30.2 → 23.2 s, spread 1.00×
- 2048 C3: ~flat (61.6 / 183 agg → 62.5 / 186)

Bounce included a process restart, so tok/s deltas are not a pure
interconnect A/B. Busbw is. Post-bounce C1 sits in the historical ~75
think-off band. KV pool unchanged: 2,740,813 tokens, 2.61× at 1M.

## Config

- `NCCL_IB_HCA` / `NCCL_SOCKET_IFNAME`: comma list of both QSFP members
- `NCCL_IB_MERGE_NICS=1`
- `NCCL_IB_GID_INDEX` unset (IPv4 RoCEv2 indexes disagree across members)
- GLOO/TP stay on a single ifname
- jumbo 9000 on both fabric netdevs
- `VLLM_EXECUTE_MODEL_TIMEOUT_SECONDS=1800`
- `TILELANG_CACHE_DIR=/cache/huggingface/tilelang-cache`
- `reasoning_effort=xhigh` aliases to `max`

## Do not

- Pin a single `NCCL_IB_GID_INDEX` on dual-HCA
- Cut over to Anemll 0.1.1 or Stage-C for this fabric win
- Compare thinking-on community C1 to this think-off table
